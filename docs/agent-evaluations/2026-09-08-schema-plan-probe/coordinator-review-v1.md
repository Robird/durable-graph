# 编排者评分 v1

编排者知道模型映射，此表不是盲评。评分依据是在答题前冻结的 [rubric](rubric-v1.md)，未依据产物调整标准。

| 条目 | sample-kestrel | sample-orchid | 核心证据 |
|---|---:|---:|---|
| R1 等价关系 | 2 | 2 | 两者均区分物理节点、完整 Key、完整布局及精确 CLR Type |
| R2 深层同 Key 冲突 | 2 | 2 | 都给出 K→J/C、叶子 scalar 不同的反例；前者遍历全部物理节点后以局部签名归纳，后者完整 canonical Shape 比较 |
| R3 共享路径深度 | 2 | 2 | 都给出浅路径先访问共享子树、深路径再次到达的反例，并计算 DAG height |
| R4 晚登记 | 2 | 2 | 每次 Execute 复核当前 Authority；缺项允许，不依赖永久 HasValidated |
| R5 权威完整布局 | 2 | 2 | 都遍历命中 Authority Node 的实际闭包，不假定子 Key 可以独立查询；明确权威物理图成本 |
| R6 依赖范围 | 2 | 2 | 全部端点与零步 owner；未使用工具被闭包覆盖；nominal Ref 不展开 |
| R7 回调前拒绝 | 2 | 2 | 完整 Schema 检查与 typeof(T) 精确相等均在首个 callback 前 |
| R8 稳定诊断 | 2 | 2 | 确定根/字段顺序、firstPath、同 Key 冲突双路径、Authority 来源路径 |
| R9 共享与成本 | 2 | 2 | 物理 memo、Key 去重查询、无路径树展开；两种方案都给出了合理开销边界 |
| R10 区分性测试 | 2 | 2 | 都覆盖深层冲突、深路径、晚登记与回调前类型失败，另有合法重复和零步场景 |
| **总分** | **20/20** | **20/20** | **未发现关键语义失分** |

## 评分之外的差异

- kestrel 用已验证的全图 Key→LocalSignature 一致性作归纳证明，额外概念较少；对相同 Key 的不同物理节点继续下降是证明的关键。
- orchid 用 exact hash-consing 产生完整 Shape，以规范身份作递归布局相等证据；它明确要求桶内精确比较，不能误读为以概率哈希代替严格相等。
- kestrel 对复杂度单独列出根出现次数 R、字段扫描量 F，还明确用显式栈和紧凑路径表示；这些是有用的交付细节，但 rubric 没把它们单列为关键门槛，不事后据此扣 orchid 分。
- orchid 额外加入输入 DTO Type 和已绑定工具的检查。题目没有要求这些新增检查；它们略增加职责，但没有破坏题目合同，不能据此判关键错误。
- 这些差异描述的是两份交付方案，不是对内部推理过程、实际 token 用量或模型一般能力的判断。

## 题目区分度的初步诊断

题目明确列出了物理节点/逻辑 Key 的区别、所有深度路径、晚登记以及 callback 前检查，并展示了可逐行审查的坏草案。这使任务更接近“在给定风险提示下设计修复”，而不是从稀疏产品需求中独立发现风险。两份答案都处理了最初预计的陷阱；这说明预设的两个陷阱对这次 Sol medium 样本不够困难。

如果继续下一题，优先测试在减少解题提示、仍保持验收合同明确的情况下，是否能自主发现跨阶段约束；应另建版本与评分，不删除或重评这对满分样本。一个样本不能证明两配置等价，也不能把未出现预期差异包装成成本节省结论。
